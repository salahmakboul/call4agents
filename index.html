Stop AI agents from repeating actions after a crash, retry or resume

Call4Agents is a small Python library for agents that send emails, take payments or change data. It sits on top of LangGraph, Pydantic AI, the OpenAI Agents SDK, MCP servers or plain Python. Each action runs once even if the agent crashes, retries or resumes; a human "yes" covers only the exact action that was shown; and you can undo a run. Standard library only.

pip install call4agents
call4agents quickstart   # offline, no API keys: 2 emails without the kit, 1 with it

Does your agent repeat an action after a crash?

call4agents crashtest your_agent.py kills your agent at every step, restarts it, and tells you which action ran twice. Your agent does not need to use the kit first. This is real output of call4agents crashtest --demo, on a small example agent. The command is experimental, and every action really runs, so use test accounts.

Real output of call4agents quickstart: an agent crashes right after sending an email, then resumes.

What it does

  • Once-only actions: an intent is written before the action and the result after; a repeat returns the result. An action interrupted half-way is reported as in doubt, never repeated blindly.
  • Approvals bound to exact arguments: one "yes" covers one action; a later "no" is enforced.
  • Idempotency keys that stay the same across crashes, for Stripe-style APIs.
  • Undo: reverse a run newest first, each undo once only.
  • Adapters for LangGraph, Pydantic AI, the OpenAI Agents SDK and MCP, tested on Linux, macOS and Windows with Python 3.10 to 3.13.

Honest limits

Version 0.5, early. Not yet proven with real payment systems in production. Several machines can share one run record in PostgreSQL; that is tested with separate processes and one local server, not yet on real networks. Every number on this site can be reproduced from the repository.
